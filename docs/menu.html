Menu

tokens/components/menu.tokens.json · generated — the CSS below is generated from the same resolved tokens driving every preview on this page, not hand-copied. Colors are CSS custom properties, not literal hex.

Not a Popover variantBuilt on Popover's exact shell (native popover attribute, border+shadow.sm+radius.default, same positioning script) but kept as its own component — a list of actions has a different content/keyboard model than arbitrary Popover content, same reasoning Modal/Drawer stayed separate despite sharing <dialog>.
Not ListboxItems here are things you do (Settings, Copy, Delete) with no persistent selection state — a list of selectable options (checkboxes, single/multi-select) is Listbox, a separate component with a different ARIA role (listbox/option vs. menu/menuitem).
Concentric radiusPanel is radius.default (8px), items are radius.xs (4px) — 8px outer minus the 4px outer padding, so a corner item's curve lines up with the panel's own curve instead of fighting it.
Destructive itemtext.danger/icon.danger at rest, and hovers into bg.danger (a pale red tint) instead of the usual fill.neutralHover — stays 'red' on hover rather than reverting to neutral gray.
Static demo onlyNo real arrow-key/type-ahead keyboard navigation or ARIA roles implemented here — this is a tokens+visual reference, not a full accessible widget. A real port needs role="menu"/"menuitem" and roving tabindex added on top.

Positioning script

Identical to Popover's — same native popover attribute, same reasoning.

document.querySelectorAll('[popovertarget]').forEach((trigger) => {
  trigger.addEventListener('click', () => {
    const panel = document.getElementById(trigger.getAttribute('popovertarget'));
    const rect = trigger.getBoundingClientRect();
    panel.style.top = (rect.bottom + 8) + 'px';
    panel.style.left = rect.left + 'px';
  });
});
