Badge

tokens/components/badge.tokens.json · generated — the CSS below is generated from the same resolved tokens driving every preview on this page, nothing hand-copied. Colors are CSS custom properties, not literal hex.

PurposeA non-interactive display pill — status/expiry indicators in Message Center's thread list, and a generic tag/label for any other product surface. Display only — no click, no dismiss.
role vs. colorTwo independent axes, never combined. role = 5 meaningful states (neutral/primary/success/warning/danger), reusing the exact same bg.*/fill.*/text.* roles Button/Card/Menu already use. color = 10 decorative hues for generic tagging, unrelated to status meaning — picking color="orange" means "I want an orange label," not "this is a warning."
tint vs. solidEvery role and color supports both: tint (pale bg + colored text, 100/600 step) and solid (saturated bg + text.onFill, 500 step) — the same intensity pair Button/Card/Menu already split into bg.* vs. fill.*.
Not ChipThe interactive filter-toggle sibling (checked/unchecked, clickable) is a separate component on purpose — a status/tag pill and a checkbox-like control are different ARIA roles, same reasoning the Menu/Listbox split already established.
Zero-to-minimal new tokensEvery role pair and 5 of the 10 color pairs (gray/blue/red/green/amber) are pure reuses of existing semantic tokens. Only orange/violet/magenta/teal/brown needed new leaf color references (tag.*, tokens/semantic/color.tokens.json).
Sizessm 16 / base 20 / lg 24 — deliberately mirrors Counter's own height/paddingX/label ladder (resolved from Counter's real values, not re-guessed) so the two small-pill components line up when they sit side by side.
