Alert

tokens/components/alert.tokens.json · inline status banner for contextual messaging inside a flow — the betslip's 'cannot include suspended outcome', 'odds have changed', 'balance too low', 'log in to place your bet'. New component. Generated — colours are --tok-* custom properties, never literal hex.

StyleA 12% colored tint (bg.*) + a colored 1px border (outline.*) + a status icon, message in white. Sits inline in the flow (e.g. the betslip footer), not docked.
Four roleswarning · negative · positive · info — mapped to the semantic status colours (warning/negative/positive) plus accent for info. The betslip uses warning for almost everything; Alert carries all four so it's reusable elsewhere.
AnatomyStatus icon → a single message line → optional close ×. No title — an Alert is one line of text in a status colour. radius.md, 12px padding, 8px gap, 20px icon.
Negative iconReuses the warning triangle for now (the UI icon set has no error-circle glyph yet); the red colour differentiates it. A dedicated glyph is a later swap.
vs. ToastAlert is a persistent in-flow banner tied to state. The solid, full-bleed app-wide bar is a Toast (--global), not an Alert.

Dismissible

The same four roles with a close × for banners the user can dismiss. That's the only other axis — an Alert is either dismissible or not.

warning · close
